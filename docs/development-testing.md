# 开发与测试约定

采用 SwiftUI 原生路线：Linux 编写源码并验证纯 Swift 逻辑，macOS CI 编译界面和执行 XCUITest。参考资料用于指导设计和评审，实际结果由对应提交的日志、断言和原始测试包证明。

先按实际需求选测试范围。普通 PR 检查最小屏 SE；手动 quick 可选一个机型，默认 SE；手动 full 维持三机型深浅色、iOS 18 和 Release 未签名构建。新增机型入口应在实际 runner 上验证设备可用和交互通过。

界面验收应保留：操作后的状态断言、持久化与边界检查；控件滚入视口后可操作；中英与默认/最大无障碍字号；深浅色和小屏；默认英语/默认字号的 Apple 无障碍审计。审计不能判断全部朗读语义、焦点顺序和辅助操作体验，仍需手工体验测试；模拟器不能证明设备硬件与性能结果。

操作后的状态变化使用有上限的条件等待，不能假定 `tap()` 返回时 SwiftUI 和辅助功能读数已同步。当前计数器逐次等待预期数值，最多 10 秒；不重新点击，超时仍失败并保留截图与界面层级。这里的超时用于功能测试，不代表真实设备响应速度达标。使用 Apple 的 [`XCUIElement.wait(for:toEqual:timeout:)`](https://developer.apple.com/documentation/xcuiautomation/xcuielement/wait(for:toequal:timeout:))；当前 CI 的 Xcode 版本支持该接口，后续测试继续保留 iOS 18 回归。

实际使用硬件或设备服务时按以下顺序实现：

1. 为所需能力定义最小协议，让业务逻辑和界面只依赖协议；沿用现有服务抽象，不预建所有硬件的空接口。
2. 分别提供真实实现与可控模拟实现；测试至少覆盖成功、失败、权限拒绝，必要时添加超时、取消和数据回放。
3. UI 测试通过显式启动参数选择测试依赖；模拟注入默认关闭，限制在测试/调试配置中，Release 使用真实依赖。
4. 对系统确实支持的模拟能力，再按官方文档使用 simctl 定位、通知、权限等接口，或 StoreKit 本地测试。区分通知载荷模拟与真实 APNs 链路、模拟定位与真实 GPS。
5. 为每项能力保留“覆盖场景、执行环境、测试证据、仍需真机验证项”。获得设备后补实测，再更新状态。

当前应用只有计数器，尚未实现这些硬件协议、mock、StoreKit 或相关场景测试。相机、传感器、蓝牙/NFC、真实链路，以及功耗、发热和手感等结果应以相应设备上的实测为准。免费账号真机签名安装和商店分发仍未验证。
